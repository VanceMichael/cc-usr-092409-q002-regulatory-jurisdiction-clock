# 消费争议数据约定

系统只保存完成争议分析所需的去标识化事实。来源事件、分类口径、商家身份映射和报告修订分别维护版本，已发布报告引用固定的数据水位。接口错误使用稳定的机器可读代码，所有持久状态进入同一 SQLite 文件。

## 管辖与期限账本约定

- **规则版本**：`rule_sets` 发布后不可变，约定法定工作日数、紧急延长上限、催办阈值与暂停依据文本。案件受理时固定适用版本；`POST /cases/:id/rule-version` 换版只影响之后追加的事件与未决定阶段。
- **时钟事件**：`clock_events` 只追加、按 `(occurred_at, seq)` 单调，不允许向已出具决定的阶段回填（`EVENT_OUT_OF_ORDER` / `STAGE_LOCKED`）。每个事件记录当时生效的规则版本，因此历史时点重算天然不受后来换版影响；阶段决定在 `stage_decisions` 另存冻结快照作为审计锚点。
- **计时口径**：一律使用 UTC 日粒度。受理当日不计入，次日起每个工作日计 1；暂停段 `[from, to)` 按整日排除（开始当日不计、恢复当日计）；暂停未结束时剩余时限冻结、不投影到期日。工作日默认周一至周五，`workday_calendar` 按 地区+日期 覆盖；每日所属负责机构以当日 00:00Z 所在责任段为准，移交后按新主办机构地区日历计数。
- **责任链**：`case_responsibility` 的部分唯一索引保证同一案件同一时刻只有一段未结束的主办责任段；`transfers` 的部分唯一索引保证同一案件只有一条在途移交。签收在单事务内完成：置移交生效、关闭旧责任段、开启新责任段、材料转为已签收、追加 `transferred` 事件。
- **材料**：移交冻结时以清单版本标记在卷材料；冻结期间到达的新材料进入待归属区（`pending_attribution`），由接收方归属。移交发起按 `idempotency_key` 幂等，签收按 移交+清单版本 幂等。
- **通知**：`notifications.dedupe_key = 案件:阶段:主办责任段:类型`，扫描重复执行、进程重启都不会重复催办；移交或进入新阶段后对新主办重新提醒。每条通知的 `basis` 留存计算口径（规则版本、消耗/剩余工作日、排除段、日历地区、负责机构）。
- **写串行化**：单连接 SQLite 上所有写事务经应用内互斥锁排队，避免异步交错嵌套事务；并发冲突由唯一约束兜底并映射为稳定错误码（如 `TRANSFER_IN_FLIGHT`、`RESPONSIBILITY_CONFLICT`、`MANIFEST_MISMATCH`）。
